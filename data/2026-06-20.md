### [1] [MonaVec: A Training-Free Embedded Vector Search Kernel for Edge and Offline AI Systems](https://arxiv.org/abs/2606.19458)
*Oğuzhan Yenen*

Main category: cs.IR | Domain: 向量检索/Vector Retrieval | Importance: 中/Medium

Ranking Relevance: MonaVec 是一项向量检索基础设施工作，与排序模型的直接关联有限。但向量检索是推荐/搜索系统中召回阶段的核心技术之一，高质量的向量检索能影响后续排序阶段的候选质量。其 4-bit 量化免训练方案对工业界边缘部署（如 on-device 推荐、离线 embedding 检索）有参考价值，且确定性保证对实验复现和 A/B 测试有吸引力。不过该工作聚焦于检索而非排序本身，对排序模型的创新无直接贡献。

  <summary>Details</summary>
Motivation: 现有向量搜索系统依赖持久化服务器、GB 级内存或对全量数据进行训练，不适用于边缘设备、离线 AI 和无网络环境。MonaVec 旨在像 SQLite 一样提供"一个文件、一个函数调用、随处运行"的轻量级确定性向量检索能力。

Method: (1) 核心量化基于随机化哈达玛变换（RHDH），将任意输入分布变换为近 N(0,1) 分布；(2) 预计算 Lloyd-Max 表实现 4-bit 量化，无需学习码本、无需数据遍历；(3) 嵌入 ChaCha20 旋转种子保证结果跨架构可复现；(4) 支持全局标准化扩展至 L2 敏感数据；(5) 可选 IvfFlat 和 HNSW 后端扩展至百万级向量；纯 Rust 实现，支持 AVX-512/AVX2/NEON/SIMD 运行时调度。

Result: 在 AG News 45K x 1024 维 BGE-M3 语义嵌入（cosine）上，4-bit BruteForce 以 27MB 达到 0.960 Recall@10，召回率领先 float32 FAISS-IVF 和 8-bit usearch，以峰值吞吐量换取字节级确定性。

Conclusion: MonaVec 填补了边缘/离线场景下确定性向量检索的空白，像 SQLite 之于关系数据一样，为向量搜索提供了"一个文件、一个调用、随处运行"的解决方案，特别适合 on-device RAG、离线 agent 和嵌入式检索。

Its quantization core is training-free by default and data-oblivious: a Randomized Hadamard Transform (RHDH) conditions any input distribution toward N(0,1), so precomputed Lloyd-Max tables quantize to 4 bits (8x smaller) with no learned codebook and no data pass. The index persists as a single .mvec file whose embedded ChaCha20 rotation seed makes results reproducible across architectures and byte-identical within a build -- a determinism guarantee that parallel-build graph libraries cannot offer.
