### [1] [PGPO: Prototype-Guided Progressive Obfuscation for Privacy-Preserving LLM-Enhanced Recommendation](https://arxiv.org/abs/2611.23236)
*Shengxiang Lin, Jiajie Su, Pengyang Zhou, Xiang Chen, Xiaolin Zheng, Feng Tian, Chaochao Chen*

Main category: cs.IR | Domain: 推荐系统/Recommender System | Importance: 中/Medium

TL;DR: 提出关系保真（relational fidelity）目标与原型引导渐进式混淆方法 PGPO，在语义嵌入上做拓扑感知的隐私扰动，用 GRPO 优化，实现强反演防御且推荐性能接近上界。

Ranking Relevance: 与排序模型的关联属于"后勤保障"层面而非模型结构层面：语义嵌入是召回（向量检索、双塔）与精排特征的重要来源，其可逆性直接带来隐私合规风险与特征可用性的权衡。方法上的启发是"保拓扑扰动"思路可迁移到跨域/跨场景表征对齐（保持相对距离、扭曲绝对坐标），避免扰动破坏排序所依赖的序关系。但实验只在物品语义侧信息上验证，未涉及真实大规模排序链路、用户行为侧隐私、扰动的训练-推理一致性（排序阶段嵌入已冻结？增量更新如何保持一致）以及在线时延/一致性问题，工业落地尚需补足。总体：对做 LLM 侧信息编码与隐私敏感场景（如个性化推荐中的描述文本）的团队有参考价值，但对排序结构创新贡献有限。

<details>
  <summary>Details</summary>
Motivation: LLM 增强推荐系统把物品文本侧信息编码为语义嵌入，但这些嵌入容易被嵌入反演攻击还原出敏感文本属性（如标题、描述中的私密字段）。现有输入侧防御依赖可信采集或本地 token 级扰动，会破坏物品间相对语义关系/拓扑结构，从而损害推荐效果。

Method: 1) 以"关系保真"为核心目标：对单个物品做足够语义偏移以保护隐私，同时保持物品两两相对关系不变以保效用；2) 为高影响力原型词学习拓扑感知的混淆锚点，并沿静态语义图传播（渐进式混淆）；3) 以 GRPO（组相对策略优化）训练，奖励由个体差异度、结构一致性、语义约束三项构成。

Result: 在两个基准数据集上取得较强的反演攻击防御效果，推荐性能接近甚至逼近无扰动上界。

Conclusion: 隐私保护与推荐效用并非只能此消彼长：将优化目标从"单点语义隐藏"改为"相对关系保真"，可在语义嵌入层面同时获得可用的隐私-效用折中。该工作为 LLM 侧信息嵌入的可部署安全性提供了可行范式。

Abstract: LLM-enhanced recommender systems encode item side information into semantic embeddings, but these embeddings may leak sensitive textual attributes through inversion attacks. Existing input-side defenses rely on trusted collection or local token perturbation, often disrupting the inter-item semantic topology needed for recommendation. To address it, we introduce relational fidelity as the key objective, requiring semantic shift for privacy while preserving relative item relations for utility. Based on this principle, we propose prototype-guided progressive obfuscation (PGPO), which learns topology-aware obfuscation anchors for high-influence prototype words and propagates them through a static semantic graph. PGPO is optimized with GRPO using individual dissimilarity, structural consistency, and semantic constraint rewards. Experiments on two benchmarks show strong inversion defense with near-upper-bound recommendation performance. The code is available at https://github.com/Shengxiang-Lin/PGPO.

We propose CONCORD-Rec, a reliability-conditioned discrete diffusion recommender supervised by counterfactual catalog-partition utility. The full-vs-uniform-T=16 sweep improves quality by 2.00-3.58% while reducing p95 latency by up to 86.89%.

TL;DR: ExecJudges 用前沿 LLM 将相关性评估指南转写为可执行程序（词法匹配 + NLP 解析器 + 池统计），替代逐文档 LLM 判定，得到快速、可复现、可审阅、低成本的自动相关性标注器；在 7 个 TREC 集合上与 NIST 标注员的一致性达到 Claude Sonnet 5.5 级别，TREC DL run 排序 Kendall's tau 0.87–0.94。

Ranking Relevance: 间接但实用价值明确：相关性标签是 LTR 训练与离线评测的基础设施。该方法以极低成本产出可复现的 relevance label / 深度池标注，可用于 (1) 搜索与推荐的离线 NDCG 评测与 run 对比，(2) 弱监督训练数据扩充与池化扩充（pool augmentation），(3) LLM judge 的成本替代与可审计化。但它本身不是排序/打分模型，不能直接用于在线排序；且程序化规则难以刻画语义匹配与用户意图，对语义型相关性任务风险较大，工业落地更现实的是"LLM judge + 程序化规则"混合分级标注体系，并按 Kendall's tau 与标注噪声容忍度做质量验收。

Motivation: LLM-as-judge 做大规模相关性标注存在三个痛点：逐文档调用前沿模型成本高、判定难以解释、难以复现。作者希望用"每个 topic 一个可读程序"来替代"每个文档一次判定"，把一次性推理成本摊薄为可检视、可复现的规则。

Method: 两阶段范式：(1) 用前沿 LLM 读取评估指南（assessment guidelines）与可选的人类标注样例，生成以词法匹配、标准 NLP 解析库、结果池统计量为唯一依赖的可执行程序；(2) 直接对文档池执行程序得到相关性标签，无额外 API 成本。变体 ExecJudges-L 引入少量每 topic 人工标签做校准/少样本。评测在 7 个 TREC 集合上，与 NIST assessor、前沿 LLM judge、per-topic 分类器对比，使用 Krippendorff's alpha 与 Kendall's tau。

Result: TREC DL 2019–2021 上与 NIST 的一致性和 Claude Sonnet 5.5 LLM judge 持平；有少量人工标签时，ExecJudges-L 在全部 7 个集合上优于同等标签量的 per-topic 分类器，Krippendorff's alpha 超过或与同等标签的 LLM judge 相差在 0.05 以内；对各 run 的排序 Kendall's tau 为 0.87–0.94；生成程序的一次性成本仅 $0.17–0.49/topic，标注零边际成本。

Conclusion: 基于"程序化 judge"的自动标注是可复现、可审阅、高效且低成本的 LLM judge 替代方案，适用于深度结果池的系统级评测与排序改进迭代。但其表达力受限于词法/统计特征，语义相关性判断仍是短板。

Abstract: Large language model (LLM) judges have become a common way to create large-scale relevance judgments for retrieval evaluation. However, each judgment requires a potentially expensive call to a frontier model, and the judgments are hard to interpret and may not be reproducible. In this paper, we ask whether an LLM can write a readable program for each topic that replaces its per-document judgments. To address these issues, we propose ExecJudges, a method for generating fast, inspectable and scalable judges for automatic relevance labeling. Specifically, ExecJudges uses a frontier LLM to turn assessment guidelines into executable programs, which rely only on lexical matching, standard NLP libraries like parsers, and pool statistics. An ExecJudges-L variant also uses examples of human labels if available. We evaluate ExecJudges on seven TREC collections by comparing the produced labels with trained NIST assessors, frontier LLM judges, and recently proposed per-topic classifiers. Our results show that ExecJudges agrees with NIST assessors at the level of the Claude Sonnet 5.5 LLM judges on TREC DL 2019-2021. With a small number of human labels per topic, the ExecJudges-L variant agrees with NIST more than per-topic classifiers with the same labels on all seven collections, and either exceeds the agreement of LLM judges provided the same labels or is within about 0.05 of it in Krippendorff's alpha. The labels rank the official TREC DL runs with Kendall's tau of 0.87 to 0.94, and writing the programs incurs a one-time cost of $0.17 to $0.49 per topic, with no additional costs for grading. Our results suggest that ExecJudges offers a reproducible, inspectable, efficient and cost-effective alternative to LLM judges for labeling deep result pools for system evaluation or ranking improvements.
