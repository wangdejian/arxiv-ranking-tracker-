### [1] [Algebraic Retrieval: Composable Search for Agents](https://arxiv.org/abs/2609.19482)
*Damian Delmas*

Main category: cs.IR | Domain: 搜索引擎/Search Engine | Importance: 低

TL;DR: 提出"代数检索"（Algebraic Retrieval）：让AI Agent在查询时以数学查询语言组合相关性、资格约束与排序偏好，并在PEM基础上演示了对比打分、候选池重排、加权排序等可组合查询，与SQL/PyTerrier实现做执行等价性验证。

Ranking Relevance: 与排序模型（LTR、多阶段排序结构）无直接关系。其"候选池重排+加权排序"作为可组合查询原语，方向上接近工业界重排/多路融合的可编程化，但本文只做执行等价性验证，未涉及特征交互、样本、损失或多任务建模，对排序模型算法本身无直接增益。潜在价值在于：为Agent驱动的检索策略编排提供统一的语义下推接口，未来可能作为重排配置层或召回-排序融合的表达工具。

<details>
  <summary>Details</summary>
Motivation: 现有检索接口（关键词、向量、SQL、检索DSL）把相关性、过滤与排序割裂成不同阶段，Agent难以在查询时按问题动态组合策略并迭代修改程序；同时缺乏对"不同实现是否真正执行同一语义"的验证手段。

Method: 构建暴露可用操作集合的代数查询面（query surface），统一表达相关性准则、资格约束、排序偏好；基于Programmatic Embedding Modulation (PEM) 将向量与打分的算术操作下推到检索执行过程。用同一批逻辑程序在代数层、SQL与PyTerrier三条路径上分别实现对比打分、候选池重排、加权排序。

Result: 在公开Vaswani数据集（11,429篇文档）上，各程序的不同实现选出完全相同的文档集合，分数差异小于1e-6；仅有一组同分文档对在不同打分路径下排序结果不同。论文明确只评估执行等价性（execution parity），不评估Agent行为或检索质量。

Conclusion: 代数检索为Agent提供了可组合、可修订的检索编排原语，并通过执行等价性验证说明其语义可被SQL/传统IR工具复现；但检索效果与Agent收益尚未被验证，属于能力型/接口型工作。

Abstract: Algebraic Retrieval lets AI agents compose search strategies at query time. Relevance criteria, eligibility constraints, and ranking preferences can be expressed together in a mathematical query. The query surface exposes available operations, so an agent can combine them for the question at hand and revise a program after inspecting results. We evaluate execution parity, not agent behavior or retrieval quality. Building on Programmatic Embedding Modulation (PEM), which exposes vector and score arithmetic during retrieval, we demonstrate contrastive scoring, candidate-pool reranking, and weighted ranking as composable queries, alongside executable SQL and PyTerrier counterparts. On the public 11,429-document Vaswani fixture, each program's implementations select the same document set with score differences below 1e-6; one tied pair orders differently across scoring paths.

### [2] [Beyond Similarity through Zero-Token Geometric Graphs for Multi-Hop RAG](https://arxiv.org/abs/2609.19622)
*Zeliang Li, Xiaofen Xing, Kailing Guo, Xiangmin Xu*

Main category: cs.IR | Domain: 召回模型/Recall | Importance: 中/Medium

TL;DR: 本文提出 G³RAG，一种无需 LLM 调用的文档级图 RAG 框架，通过几何增益分数（cosθ·sinθ）构建图边，结合密度感知拓扑惩罚与单步受控扩散，实现高效多跳证据检索，在 MusiQue、2WikiMultiHopQA、HotpotQA 上取得图基基线中最优平均 F1 与命中率。

Ranking Relevance: 该工作位于召回/检索侧：作为多跳 RAG 的证据检索与图扩展模块，可视为候选生成阶段（多跳文档召回）的改进。其核心思想对搜推广排序链路有三点借鉴价值：（1）用 cosθ·sinθ 这类几何增益刻画"相关但正交"的多样性信号，可迁移到 MMR 式多样性打散、重排（reranking）中的互补性建模；（2）密度感知拓扑惩罚与 hub 抑制，与推荐中热门物品流行度去偏、图神经召回中的度数归一化同源；（3）"单步受控扩散"给出了轻量、可控的候选扩展深度策略，可类比检索中的 query 扩展或 session 图扩散。不过它不涉及排序模型结构、特征交叉或多任务预估，对 CTR/CVR 排序主模型不产生直接影响，主要用于召回/重排与 RAG 证据组织环节。

<details>
  <summary>Details</summary>
Motivation: 多跳 RAG 需要既相关又具新颖性的证据来弥合语义鸿沟：稠密检索偏向语义相似文档，易陷入同质化；图方法依赖昂贵的 LLM 实体抽取，且会沿噪声连接传播。作者希望在不依赖 LLM 建图的条件下实现高效的多跳证据发现。

Method: G³RAG 为仅基于文档的框架，离线构图不使用 LLM 调用或生成 token。每条边赋予几何增益分数 cosθ·sinθ，同时刻画文档表示间的方向一致性与正交性；引入密度感知拓扑惩罚抑制高度连接的枢纽节点；从过滤后的查询种子出发，做单步受控扩散以扩展到互补证据。

Result: 在 MusiQue、2WikiMultiHopQA、HotpotQA 上，使用 Nv-embed-v2 与 Qwen3-8B-embed 两种嵌入设置，G³RAG 均取得图基基线的最高平均 F1 与答案文档命中率，平均性能最高提升 4.26 F1 点，MusiQue 上提升 5.76 点，同时消除了实体图方法的建图 token 成本。

Conclusion: 几何结构可支撑高效多跳证据发现，无需依赖 LLM 建图；说明图构建中的方向-正交几何信号与拓扑去噪，是替代昂贵实体抽取路线的可行方案。

Dense retrieval tends to concentrate on semantically similar documents, whereas graph-based alternatives often depend on costly Large Language Model (LLM) entity extraction and may propagate through noisy connections. G$^3$RAG assigns each edge a geometric gain score, $\cosθ\cdot \sinθ$, that jointly captures directional consistency and orthogonality between document representations. A density-aware topological penalty suppresses highly connected hubs, while single-step controlled diffusion expands from filtered query seeds toward complementary evidence. We evaluate G$^3$RAG on MusiQue, 2WikiMultiHopQA, and HotpotQA using Nv-embed-v2 and Qwen3-8B-embed. G$^3$RAG obtains the best average F1 and answer-document hit rate among the evaluated graph-based baselines in both embedding settings, with gains of up to 4.26 F1 points in average performance and 5.76 points on MusiQue. It also removes the graph-construction token cost incurred by entity-based graph methods. These results show that geometric structure can support efficient multi-hop evidence discovery without LLM-based graph construction. Code is available at https://anonymous.4open.science/r/G3RAG-99D9/

### [3] [Self-Evolving Search Index](https://arxiv.org/abs/2609.19656)

Main category: cs.IR | Domain: 召回模型/Recall | Importance: 中

TL;DR: 提出SELF-INDEX框架，让检索索引无需人工干预即可自演化：Optimizer自主诊断检索失败、选择性修订索引键并验证后更新；Query Simulator主动挖掘潜在查询需求，使索引超越已有查询进行演化。多语料、多检索器上稳定提升检索性能，并改善搜索Agent与记忆系统效果。

Ranking Relevance: 该工作位于召回/检索侧（index key与文档表征），不直接改排序打分，但通过改进索引键质量与检索环境适配性，可提升召回集合质量（recall/准确率），进而影响后续粗排、精排的输入分布与上限，对RAG式搜索Agent与记忆召回链路具有潜在工程价值。

<details>
  <summary>Details</summary>
Motivation: LLM Agent处理复杂任务时信息需求多样，检索质量高度依赖索引键如何表征文档知识；而有效索引表示随检索环境变化，单一固定优化策略难以普适。现有索引演化仍主要靠人工：人工诊断检索失败、调整优化策略、重处理索引，成本高且不可扩展。

Method: SELF-INDEX由两部分组成：(1) Optimizer——自主诊断检索短板，定位并选择性修订负责的索引键（修订而非全量重处理），每次修订先验证有效性再更新索引；(2) Query Simulator——在已观测检索需求之外主动模拟/探索新查询，驱动索引向前演化。整体形成"诊断—修订—验证—更新"的自演化闭环。

Result: 在多种语料与多种检索器设置下，SELF-INDEX一致提升检索性能，优于现有索引优化方法；增益可迁移到下游应用，提升搜索Agent的有效性与效率，并帮助Agent记忆系统更有效地召回有用历史交互。

Conclusion: 索引演化可从人工驱动转为自动闭环，通过对索引键的选择性、经验证的修订以及查询侧的主动模拟，实现检索性能与下游Agent效果的持续提升。

Abstract: Information retrieval is increasingly important as LLM agents tackle complex tasks involving diverse information needs. Because retrieval relies on an index that represents each document through index keys, retrieval quality depends heavily on how effectively these keys expose the knowledge contained in each document. Yet evolving an index to its retrieval environment remains largely human-driven, requiring humans to diagnose retrieval failures, refine the optimization strategy, and reprocess the index accordingly. We propose SELF-INDEX, a framework that enables an index to self-evolve without human intervention. Its Optimizer autonomously diagnoses retrieval shortfalls, selectively revises the responsible index keys, and validates each revision before updating the index. Beyond reacting to observed retrieval demands, SELF-INDEX proactively explores additional demands through a Query Simulator, allowing the index to evolve beyond the queries already available for optimization. Across diverse corpora and retrievers, SELF-INDEX consistently improves retrieval performance while outperforming existing index optimization methods. We further show that these benefits extend to downstream applications, improving the effectiveness and efficiency of search agents and helping agent memory systems retrieve useful past interactions.
