### [1] [SilentProbe: Measuring Silent Failure in Production APIs Used as Agent Tools](https://arxiv.org/abs/2609.00035)
*Zongrong Li, Shengkun Ye, Feiyou Guo, Zuoyou Dang*

Main category: cs.IR | Domain: 其他/Other | Importance: 中/Medium

TL;DR: 本文研究了LLM Agent在调用生产环境API时无法区分"查询无匹配"和"服务器不理解查询"的问题（两种情况都返回HTTP 200）。通过审计721,320个参数（来自2,501个OpenAPI文档）、对27个供应商的219个schema扰动实验，发现约束形式（而非供应商身份）决定诚实性：机器可检查的约束111/111次产生诚实错误，纯文本约束44/61次静默失败。实验还发现，schema中仅以示例形式出现的词汇在所有模型中88/88次全部失败，而完整列出的词汇正确使用率88-91%。模型仅能检测12%的静默失败、修复0%、向用户断言错误负面结果41%、捏造数字12%。修复方式是将词汇提升到schema中，可将失败从88/88降至0/89——一行schema修复而非换个更好的模型。

Ranking Relevance: 该论文不直接涉及排序/召回/预估等ranking核心问题，但对工业推荐和搜索系统有间接但重要的启示：(1) 在搜推广系统中，LLM Agent越来越多地用于智能化交互（如自然语言搜索、对话式推荐），本研究中揭示的API schema约束缺陷可能导致Agent在与搜索/推荐后端交互时产生静默失败和误导性输出，直接影响用户体验和系统可信度。(2) 论文的核心洞见——"修复schema而非更换模型"——与工业界在排序系统中处理特征工程和样本质量问题时"先修数据/特征再调模型"的理念高度一致，启示搜推广从业者应优先保证接口和数据的机器可检查约束，而非单纯追求模型改进。(3) 对于构建面向LLM Agent的搜索/推荐API服务（如将内部检索能力以OpenAPI暴露给Agent的场景），本文提供了系统性的schema设计最佳实践参考。

  <summary>Details</summary>
Motivation: LLM Agent在生产系统中的应用日益普及，但Agent无法区分API返回"无结果"和"不理解请求"这两种语义上截然不同的情况。这导致Agent可能向用户谎报结果、捏造数据，造成严重的可靠性问题。作者希望系统化地量化这种静默失败的规模、原因以及可能的修复方案。

Method: 1) 大规模审计2,501个OpenAPI文档中721,320个参数的约束声明情况（枚举、机器可检查约束、纯文本约束）；2) 构建Monid聚合层，对27个真实商业供应商的实时端点施加219个schema派生扰动，对比机器可检查约束与纯文本约束的诚实错误率；3) 让12个模型（8个家族）在这些端点上执行普通任务，测试示例式词汇vs完整列出词汇的准确率；4) 运行完整的Agent循环，测量检测率、修复率、错误断言率和捏造率；5) 验证将词汇提升至schema的修复效果。

Result: 7.5%的参数声明了枚举，15.2%声明了任何机器可检查约束，40.1%的文档在文本中描述约束但schema未编码。机器可检查约束111/111次产生诚实错误，纯文本约束44/61次静默失败（p=2e-13）。示例式词汇88/88次全部失败，完整词汇88-91%正确。完整Agent循环中：检测率12%、修复率0%、错误负面断言41%、捏造12%。将词汇提升至schema后失败从88/88降至0/89。

Conclusion: LLM Agent与API交互中的静默失败是一个系统性的、可量化的可靠性问题，其根源在于API schema（OpenAPI文档）中约束表达的不足，而非模型能力的不足。修复方案集中在改进schema本身的表达能力——一行schema变更就能彻底消除失败，这比追求更强大的模型更为有效和经济。

Abstract: An LLM agent calling a production API cannot distinguish a query that matched nothing from a query the server did not understand. Both return HTTP 200 with a parsable body, no exception to catch and no field to branch on. We ask what predicts which one occurred, and what it does to the agent. Auditing 721,320 parameters across 2,501 independently published OpenAPI documents, we find that 7.5% declare an enumeration and 15.2% declare any machine-checkable constraint at all, while 40.1% of documents state at least one constraint in prose that their schema does not encode. Executing 219 schema-derived perturbations against live commercial endpoints from 27 vendors, reached through a single aggregation layer (Monid) that publishes a schema and returns a run identifier for every call, we find that constraint form, not vendor identity, predicts honesty: machine-checkable constraints yielded an honest error in 111 of 111 cases, prose-only constraints failed silently in 44 of 61 (p = 2e-13). A vocabulary that the description merely exemplifies was missed by every model on 88 of 88 attempts, while vocabularies written out in full were used correctly 88 to 91% of the time. Running the full agent loop, models detected the resulting silent failure in 12% of cases, repaired it in 0%, asserted a false negative to the user in 41%, and invented a figure in 12%. Promoting the vocabulary into the schema removes the failure, from 88 of 88 to 0 of 89. The fix is one line of schema rather than a better model. Code, schemas, perturbation sets, agent transcripts and per-call run identifiers are released at https://github.com/Jasper0122/silentprobe.

### [2] [Two-Sided State-Space Models for Sequential Recommendation with Non-Random Multimodal Review Feedback](https://arxiv.org/abs/2609.00165)
*Ziwen Pan, Zihan Liang, Ruoxuan Xiong*

Main category: cs.IR | Domain: 推荐系统/Recommender System | Importance: 中/Medium

TL;DR: 本文提出TS-SSM（双端状态空间模型），用于事件条件下的序列推荐。针对传统序列推荐将评论仅视为被动信号的问题，TS-SSM同时建模评论生成的非随机性（缺失非随机机制）以及评论对用户和物品动态状态的塑造作用，包含三大模块：评论内容与观测模式编码、基于时间变化和局部图传播的用户状态演化、以及正负评论非对称影响的物品状态演化。在六个Amazon类别上Recall@20相比BSARec提升14.8%-18.8%，在Goodreads上大幅超越SOTA。

Ranking Relevance: 该论文聚焦序列推荐任务，与排序模型相关但并非直接的点击率/转化率预估或精排模型。其相关性体现在：(1) 双端状态建模思路对动态环境下用户/物品表征的实时更新有借鉴意义，可迁移到工业场景中利用反馈信号（如评论、互动行为）动态调整排序特征；(2) 缺失非随机（MNAR）建模思想在工业CTR预估中处理特征缺失（如冷启动、曝光偏置）时具有直接参考价值，可用于缓解训练-推断偏移；(3) 局部图消息传播类似利用物品间关联（如同品类、共现关系）增强排序模型的特征交互能力。但由于实验聚焦长序列评论场景、且评估为Recall@20而非工业标准的AUC/GAUC等排序指标，其直接可部署性有限，更多是提供方法论启示。

<details>
  <summary>Details</summary>
Motivation: 双端数字平台本质上是动态的：用户偏好、物品流行度都在变化，评论既反映也驱动这些变化。然而现有序列推荐系统大多将评论视为更新用户状态的被动信号，忽略了两点：(1)评论生成是非随机的，取决于用户和物品双方变化的潜在状态；(2)评论能重塑物品状态、在相关物品间产生溢出效应，并影响未来用户决策。作者旨在填补这两个研究空白。

Method: TS-SSM包含三个核心组件：(1) modality-missing-not-at-random融合模块：编码评论内容及信息性的观测模式，刻画评论缺失并非随机；(2) 用户状态演化：建模时间维度上的变化，并通过局部图消息传递利用相关物品状态来精炼用户偏好；(3) 物品状态演化：对正面和负面评论反馈引入非对称的遗留/传递效应（即正负评论对物品后续状态的影响不同）。整个框架是一个双端（用户+物品）状态空间模型，在事件（评论、交互）条件驱动下完成序列推荐。

Result: 在六个Amazon商品类别上，TS-SSM相比BSARec在Recall@20上提升14.8%-18.8%，相比HM4SR平均提升11.7%。在Goodreads Fantasy数据集上Recall@20从HM4SR的0.5191提升至0.5847。消融实验验证了观测模式编码、局部图传播和物品动态三者的独立贡献。

Conclusion: 该工作证明了在序列推荐中评论不应仅被视为被动用户信号，而应作为驱动用户和物品两侧状态协同演化的主动事件来建模。通过显式建模评论缺失非随机性、用户-物品双端相互影响的动态演化，以及正负反馈的非对称传导，显著提升了推荐精度。

Abstract: Two-sided digital platforms are inherently dynamic: user preferences shift, item popularity evolves, and reviews both reflect and drive these changes. Yet most sequential recommendation systems treat reviews as passive signals for updating user states, leaving two aspects underexplored. First, review generation is nonrandom, depending on evolving latent states of both users and items. Second, reviews can reshape item states, induce spillover across related items, and influence future user decisions. To address these gaps, we propose a two-sided state-space model (TS-SSM) for event-conditioned sequential recommendation. TS-SSM consists of three components: (1) a modality-missing-not-at-random fusion module that encodes review content and informative observation patterns; (2) user-state evolution with temporal variation and local graph message passing that uses related item states to refine user preferences; and (3) item-state evolution with asymmetric carryover of positive and negative review feedback. In experiments across six Amazon categories, TS-SSM increases Recall@20 over BSARec by 14.8%--18.8% and exceeds HM4SR by 11.7% on average. On Goodreads Fantasy, Recall@20 improves HM4SR from .5191 to .5847. Ablations highlight distinct contributions of observation patterns, local propagation, and item dynamics.

### [4] [Closed Forms and Synthetic Twins: Predicting Approximate Nearest Neighbor Recall from Embedding Statistics](https://arxiv.org/abs/2609.00364)
*Shmuel Herman*

Main category: cs.IR | Domain: 向量检索/Vector Retrieval | Importance: 高/High

TL;DR: 本文揭示了一个关键问题：嵌入模型在训练和评估时假设精确检索，但在生产环境中实际部署在近似索引（HNSW、IVF、乘积量化PQ或后交互模型FDE）之后，编码器基准测试无法预见索引行为——实验显示一种现代编码器通过FDE索引只能恢复其精确top-10结果的14%。论文提出了一个"仪器阶梯"（ladder of instruments），在构建索引之前即可从无标签的原始嵌入统计中预测索引行为：(1) 对PQ/FDE等固定网格量化器使用闭式矩统计；(2) 对分区索引使用合成孪生语料仿真；(3) 对百万文档规模的图索引使用尺寸外推、轻校准的孪生体。预测在未见过的百万文档语料上的召回率误差在0.03以内。此外，该几何特征是可通过训练优化的：针对后处理变换无法改变的唯一统计量——分数边际（score margin）——进行优化，可以一次性提升所有索引族的召回率，同时任务代价很小。最终效果：通过一次廉价测量即可完成索引选择、纠错定价和生产召回率预测；无需每个语料配备变换机制，适用于持续变化的语料；通过将编码器适配于几何特征而非耦合到单一索引来推动召回-计算前沿。

Ranking Relevance: 与排序/预估模型存在深层关联。首先，召回（recall）是精排的上游阶段，召回链路的质量直接决定进入排序漏斗的候选质量；本文揭示"评估-服务"不一致导致的召回损失，对工业级"召回→粗排→精排"pipeline中召回环节的可控性有直接价值。其次，"分数边际"作为对所有后处理不可变、可训练的几何统计量，为召回编码器的训练目标提供了新视角——这与排序模型中通过margin/校准优化（如pairwise loss、校准偏差控制）的精神一致。第三，论文所提"事先预测生产召回率"的方法可直接用于工业系统中召回索引升级/替换前的成本-收益评估，避免线上事故。第四，预测召回率可用于精排前更好的纠错/重排序决策定价，和动态算力分配（如根据可预测的召回质量调整精排深度或模型复杂度），具有较强的工程落地价值。
